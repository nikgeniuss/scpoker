## ✅ Починено 2026-09-02 (проверить на следующем прогоне)

### 0. Балансировка ломала стол игрока: пересадка в чужую раздачу, зависшая пилюля, экран на пустом столе

**Симптомы (со слов игрока, повторялось КАЖДЫЙ раз при балансировке).** Игроки пропадают из-за
стола, появляется «ждём второго игрока»; слышны звуки чужих ходов; возникает вторая узкая пилюля
без карт, подсвеченная как «мой ход»; по клику открывается стол, где ход мой, **но карт нет**; со
следующей раздачи карты приходят и пилюля становится нормальной, а прежняя висит до перезагрузки.

**Три независимых дефекта в `movePlayerToTable`:**

1. **Клиент не переезжал.** `TOURNAMENT_TABLE_ASSIGNED` слал сервер, но обработчика в `client/src`
   не было ни одного — событие мёртвое. На турнирный стол клиент попадал только ручным кликом из
   [Tournaments.tsx:100-101](../client/src/pages/Tournaments.tsx#L100-L101). Игрока пересаживали на
   сервере, а экран оставался на старом столе — который в этот момент пустел.
2. **Пилюля старого стола висела вечно.** `sock.leave(fromRoomId)` выполнялся **до**
   `broadcastGameState(fromRoomId)`, поэтому финальное состояние «меня тут нет» до клиента не
   доходило, а `tablesStore.observe` удаляет пилюлю именно по этому признаку.
3. **Посадка в идущую раздачу без карт.** Проверялся только исходный стол
   (`fromRoom.status !== 'waiting'`), целевой — нет; игрок клался прямо в `toRoom.players` в обход
   `addPlayer`/`seatTournamentPlayer`, где для late entry ставится `isFolded: true`. Итог:
   `isFolded: false` + пустые карты → `nextPlayer` не пропускал → ход игроку без карт.

**Что сделано.**
- `movePlayerToTable(from, to, userId, allowMidHand = false)`: без флага перенос в играющий стол
  откладывается (`toRoom.status !== 'waiting' → false`); с флагом (только консолидация, где ждать
  негде) игрок садится `isFolded: true`, `cards: []`, `currentBet: 0`.
- `closeAndRedistribute` вызывает перенос с `allowMidHand = true`, обычная балансировка — без.
- `broadcastGameState(fromRoomId)` перенесён **до** `sock.leave(...)`; в payload события добавлен
  `fromRoomId`.
- Клиент: [TablesManager.tsx](../client/src/components/game/TablesManager.tsx) слушает
  `TOURNAMENT_TABLE_ASSIGNED` — убирает пилюлю старого стола и, если игрок сейчас смотрит именно на
  него, показывает тост «Вас пересадили за другой стол» и уводит на новый.
- Пустая пилюля больше не схлопывается (`min-w-9`).
- Тесты: 2 новых в [GameManager.tournamentMove.test.ts](../server/src/game/__tests__/GameManager.tournamentMove.test.ts)
  (блокировка переноса в играющий стол; `allowMidHand` → folded, без карт, ход не достаётся). Файл
  зелёный: 7 тестов.

**Проверить живым прогоном:** MTT на 2+ столах, дождаться и переноса одного игрока, и консолидации
стола — экран должен сам переехать с тостом, старая пилюля исчезнуть, ход без карт не появиться.

### 0б. Турнир создавался дважды при двойном submit

**Что было.** Два «Тест2» с одинаковыми параметрами, созданы с разницей **514 мс**
(`uHzOkmCHpL` 23:58:58.022Z и `bxl8MG2wsp` 23:58:58.536Z). Оба независимо запланировали по 15
ботов, набрали игроков, доиграли до конца и **оба выплатили по 10000 overlay** — двойной клик
стоил руму 10000 фишек лишних выплат.

**Причина.** Кнопка `type="submit"` без `disabled`, локального состояния «отправляется» в модалке
не было, а сама модалка закрывалась только **после** `await createTournament(...)`
([Tournaments.tsx:33-41](../client/src/pages/Tournaments.tsx#L33-L41)) — всё время запроса кнопка
принимала повторные клики. Серверной дедупликации не было: каждый `POST /admin/tournaments`
безусловно создавал новую запись. (Enter в полях сабмит не отправлял — он гасился ещё до фикса,
так что источник ровно один: двойной клик/тап.)

**Что сделано.**
- Клиент: состояние `submitting`, кнопка блокируется и показывает «Создание…» до ответа сервера.
- Сервер: `findRecentDuplicate` в `TournamentManager.create` — повторный запрос того же админа с
  теми же ключевыми параметрами (name/type/buyIn/startingStack/tableSize) в окне
  `CREATE_DEDUP_WINDOW_MS` = 5 с возвращает **уже созданный** турнир, а не второй такой же
  (идемпотентно, в лог идёт `[tournament-create-dedup]`).
- Enter в поле теперь ещё и снимает фокус — на мобиле/TWA сворачивается клавиатура, значение
  принято, создание — только явным нажатием кнопки.
- Тесты: 3 серверных в [TournamentManager.mtt.test.ts](../server/src/game/__tests__/TournamentManager.mtt.test.ts)
  (повтор → тот же id; другой админ/другие параметры → отдельные турниры; вне окна → новый
  турнир) и 2 клиентских в [CreateTournamentModal.test.tsx](../client/src/components/lobby/CreateTournamentModal.test.tsx)
  (Enter не создаёт турнир и снимает фокус; тройной клик → один вызов).

**Проверить живым прогоном:** быстро кликнуть «Создать» дважды — должен появиться ровно один
турнир; Enter в поле — клавиатура сворачивается, турнир не создаётся.

### 0в. Running-турнир не переживал рестарт сервера — висел навсегда

**Что было.** «Тест1» (`ZqRBIbElf0`) после рестарта: стол пустой, 7 записей `playing`, блайнды
докрутились по всей лестнице до потолка 10000/20000 и встали. Живой игрок мог выйти форфейтом,
боты — нет: их некому вывести, `finish()` не наступал никогда. Авто-уборка такой турнир не
трогает (она только для `finished`/`cancelled`), watchdog тоже — активной раздачи нет, значит
формально стол не «завис».

**Причина.** Состав турнирного стола существует только в памяти `GameManager`: `rooms.json`
хранит конфиг стола без игроков, и при восстановлении `makeRoom(...)` создаёт пустой стол.
Вернуть людей и ботов мог лишь `restoreActiveHands()` → `applyActiveHandSnapshot`, а он
срабатывает только для столов, у которых **в момент снапшота шла раздача** и запись удалась.
«Тест1» не попал ни в один снимок — и восстанавливать его стало нечем.

**Что сделано.**
- `TournamentEntry.chips` (shared) — турнирный стек участника теперь персистится.
- `GameManager.onTournamentStacks` — новый хук: в `cleanupHand` турнирный стол отдаёт актуальные
  стеки, `TournamentManager.syncStacks` пишет их в `entries` (+ `persist`).
- `TournamentManager.reseatTables` в `restoreTournaments` — сажает обратно всех `playing`, кого
  нет за своим столом, с сохранённым стеком (у турниров, начатых до этой правки, — со стартовым,
  иначе они не вернулись бы вовсе), и возобновляет игру через `startGame`. Столы, поднятые
  снимком раздачи, не трогаются: они уже не пусты.
- `GameManager.getSeatedPlayerIds` — чтение фактического состава стола.
- Восстановление больше не зависит от того, застал ли рестарт активную раздачу и удалась ли
  запись `active-hands.json` (см. п.1 про EPERM — раньше эти два фактора совпали и убили турнир).

**Проверено вживую:** после правки «Тест1» на рестарте пересадил 6 игроков, доиграл раздачи и
завершился штатно — `prizePool=10000 (оверлей +6000), выплаты #1=5455, #2=2727, #3=1818`.

**Тесты:** [TournamentManager.restart.test.ts](../server/src/game/__tests__/TournamentManager.restart.test.ts)
— пересадка за свои столы после рестарта; посадка с сохранённым стеком, а не стартовым; выбывших
обратно не сажает. Полный серверный прогон — 1042 теста зелёные.

### 0г. EPERM при записи `active-hands.json`, двойной лог блайндов, нечитаемые турнирные логи

**EPERM (был 🔥).** 5 срывов флаша за прогон, все по самому горячему `active-hands.json`, два подряд
с разницей ~450 мс. Причины две: флаши одного файла шли **внахлёст** (дебаунс схлопывал вызовы, но
не ждал завершения предыдущей записи — два `rename` на один путь), и не было ретрая на
транзиентные ошибки Windows, когда хендл держит Defender/индексатор.
Починено в [storage.ts](../server/src/auth/storage.ts): очередь флашей per-file + ретрай `rename`
(20/60/150 мс) на `EPERM`/`EBUSY`/`EACCES`; содержательные ошибки (например `ENOSPC`) не ретраятся.
Тесты — [storage.test.ts](../server/src/auth/__tests__/storage.test.ts) (5): ретрай доводит запись
до конца, лимит попыток не молчит, `ENOSPC` не ретраится, второй флаш ждёт первый, разные файлы
пишутся независимо.

**Двойное повышение блайндов.** `setTimeout` просыпается на ~1 мс раньше границы уровня →
`currentLevelForElapsed` отдаёт старый уровень → он рассылался и логировался повторно. Добавлен
`appliedLevel` в runtime турнира: рассылка и лог только при реальной смене уровня; поле
проставляется и при старте, и при восстановлении. Граничное поведение расписания закреплено
тестами в [tournamentSchedule.test.ts](../server/src/game/tournament/__tests__/tournamentSchedule.test.ts).

**Логи.** Во все турнирные строки добавлен `id` (одноимённые турниры больше не путаются), в
`[tournament-bust]` убийца печатается ником вместо сырого `userId`.

**Правило про ботов.** §0.11 CLAUDE.md приведён к факту: `'minus'` — легальный таргет для
турнирных ботов (`bot:fill-*`, `bot:tt-*`), сила крутится через `TOURNAMENT_BOT_WEAKNESS`.

### 0д. Overlay — эмиссия фишек без следа в учёте

**Что было.** Гарантия доплачивается на финише (`prizePool += overlay`), приз кредитуется игроку —
фишки создаются, ниоткуда не списываясь. Единственный след — `overlayPaid` внутри турнира, который
исчезает вместе с турниром при уборке из лобби. За прогон так растворилась эмиссия 20000 (из них
10000 — из-за бага с дублем турнира, п.0б).

**Что сделано.** Новый журнал [tournamentLedger.ts](../server/src/game/tournament/tournamentLedger.ts)
(`server/data/tournament-ledger.json`, cap 500): строка на завершённый турнир — входы, уникальные
игроки, собрано за входы, рейк, баунти, оверлей, призовой, выплачено и `net = рейк − оверлей`.
Запись при `finish()`, идемпотентна по `tournamentId`. Чтобы было что писать, суммы теперь копятся:
`collectedFees`/`collectedRake`/`collectedBounty` в `TournamentInfo`, единая точка кредита входа —
`creditEntryFee` (вместо семи разрозненных `prizePool +=`).
Эндпоинт `GET /admin/tournament-ledger` (журнал + итоги), UI —
[TournamentLedgerSection](../client/src/components/admin/TournamentLedgerSection.tsx) внизу вкладки
«Данные»: сводка (турниров / рейк / оверлей / итого руму) и таблица по турнирам.
Тесты — [tournamentLedger.test.ts](../server/src/game/__tests__/tournamentLedger.test.ts) (7).

### 8. ✅ TG-бот: `getUpdates failed` (429 и Bad Gateway) — закрыто 2026-09-06

Разово `Too Many Requests: retry after 5`, затем три `Bad Gateway` подряд. Оказалось не только
стороной Telegram: `retry_after` из ответа до кода не доходил, бот на любую ошибку ждал
фиксированные 5 секунд. Теперь пауза берётся из ответа, а на обычных обрывах растёт от 1 с до
минуты и сбрасывается на первом успехе ([pollBackoff.ts](../server/src/bot/pollBackoff.ts),
подключён в [telegramApi.ts](../server/src/bot/telegramApi.ts)); короткие разрывы long polling
больше не пишутся в лог как ошибки.

## Как воспроизводить и наблюдать

Сервер пишет турнирные события в stdout. Для наблюдения — запуск с логом в файл и фильтр:

```bash
npm run dev > dev.log 2>&1
tail -n 0 -f dev.log \
  | grep -avE "TG bot: getUpdates failed" \
  | grep -aE --line-buffered "\[tournament-|\[promo-|app crashed|nodemon.*restarting|Error:|EADDRINUSE|UnhandledPromiseRejection|TypeError|ReferenceError|FATAL"
```

Общий тег `[blind]` в фильтр не брать — он ловит блайнды кэш-столов ботов и топит турнирные
события; уровни турнира идут под `[tournament-blinds]`.

**Важно:** не читать `server/data/active-hands.json` во время игры — чтение провоцирует EPERM (п.3).
